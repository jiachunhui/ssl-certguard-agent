## Nginx 证书部署逻辑重构 — 需求分析（未改代码）

用户提出 NginxProvider 重构需求（当前实现只写证书文件、不改 nginx 配置），待确认后实施：

1. **需求1**：nginx 无相关域名 → 不处理（跳过）
2. **需求2**：有域名且有 443 → 只替换 ssl_certificate / ssl_certificate_key 路径
3. **需求3**：有域名只有 80 → 复制 80 块创建 443 块（listen 443 ssl + 证书指令）
4. **需求4**：有域名、有证书但 listen 非 443 → 只替换证书路径

关键分析结论：
- 当前 `NginxProvider.DeployAsync` 仅匹配 server_name（精确 Contains，忽略大小写）并写 `/etc/nginx/ssl/<主域名>/{fullchain,privkey}.pem`，不修改任何配置文件（docs/05-实践教程/Nginx证书部署.md 明确写明该行为）
- `ParseServerNames` 不跳过注释（`#`），存在误匹配风险（重构时需修）
- 配置扫描范围仅 conf.d / sites-enabled / nginx.conf，include 嵌套到其它路径扫不到
- 版本策略：生成新块遵循"最小公分母"（`listen 443 ssl;` 不带 http2/ssl on/ssl_protocols），对已有块只改证书路径不重写 listen → 跨版本安全。版本边界：`listen ... http2` 于 1.25.1 弃用、1.27.0 移除（emerg）；`ssl on` 于 1.15.0 弃用；`default_server` 0.8.21+；老通配符 `.example.com` 仍兼容
- 需前置检测 `nginx -V` 是否含 --with-http_ssl_module，缺失则不能创建 443 块
- 安全机制：修改前备份原文件 + `nginx -t` 失败自动回滚

待用户确认问题：匹配规则（通配/正则）、纯重定向 80 块处理、多块匹配选模板、default_server / IPv6 继承、include ssl 配置是否跟随、SAN 多域名独立块的替换范围等。

## 用户确认结论（方案已定，待实施）
- 匹配规则：精确 + 通配（双向：证书 `*.example.com` 条目 ↔ server_name `www.example.com`），正则不处理
- SAN = domains 数组（平台把证书全部域名含通配符都下发，与 SAN 同一概念）
- 部分匹配即部署匹配的、跳过未匹配的；全部未匹配 → 失败上报（与 IisProvider 逻辑一致，已核实 IIS 代码）
- 替换证书路径只发生在匹配域名的 server 块内；所有匹配块替换为同一路径（主域名目录）
- listen 带 ssl 但无 ssl_certificate（含 include ssl.conf）→ 跳过+警告上报，文档记录手动方案
- 80 纯重定向块 → 不创建、报错上报，文档记录手动方案
- 同一 server_name 多 80 块 → 优先选非重定向完整块做模板
- default_server 不继承到新 443 块（零影响现有应用）
- IPv6：80 块有 listen [::]:80 → 成对生成 listen [::]:443 ssl
- 新块只写：listen 443 ssl（+IPv6 可选）+ server_name 原样 + 原块指令（剔除 return/rewrite 跳 https）+ 两行证书路径；不写 http2/ssl_protocols/ssl on
- 修改前备份 + nginx -t 失败自动回滚；sites-enabled symlink 解析真实文件；绝对路径引用证书
- 创建粒度：按 server 块，每块最多创建一次（多域名命中同一块去重）
